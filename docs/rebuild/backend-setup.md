The code runs without credentials and reports online booking/payment unavailable. Production never substitutes the recruiter sandbox. Local PostgreSQL tests verify the migration and transaction invariants; they do not establish working Supabase OAuth, SMTP, Razorpay mandates, refunds or deployed webhooks. Those require the final activation gate below.

A stale old URL does not enable the new backend. Service-role and Razorpay secrets must never use `NEXT_PUBLIC_` names or be pasted into chat, logs, source, screenshots or commits.

Enable Google OAuth with the new project's callback on Google's credential settings. Configure custom SMTP, sender domain authentication and email magic links. ## Razorpay test configuration

- Set `ACADEMY_PAYMENT_MODE=test`, test key ID/secret, and webhook secret. Configure automatic capture. Court orders are created on the server with integer paise, INR, immutable amount, unique attempt receipt and private attempt note. Browser confirmation must pass HMAC verification and an API-fetched captured payment matching the persisted order/amount/currency. Authenticated payment alone is insufficient. An expired/cancelled hold cannot be revived: a late captured payment creates a durable refund job.
- Create a monthly interval-one INR2500 plan; set its plan ID. The server checks the fetched plan amount/currency/cadence before subscription creation. Razorpay requires a finite `total_count`; this implementation uses 120 monthly cycles (ten years) with auto-renewal until cancellation/completion. There are no free court entitlements or banked credits. Benefits start only after an API-fetched captured INR2500 payment on a paid subscription invoice with a verified billing period. The unpaid authentication charge and `subscription.activated` event alone grant nothing.
- Enable endpoint `https://<canonical-host>/api/payments/webhook` for `payment.captured`, subscription lifecycle events (especially `subscription.charged`, pending/halted/cancelled/completed), and refund events. Use the original raw body signature and `x-razorpay-event-id`. Rotate webhook secrets with the previous-secret environment slot until older retries are exhausted. Never log payment payloads; stored event payloads are private and access-restricted.
- Court and subscription creation are not assumed provider-idempotent. The database allows only one attempt per reservation/membership and serializes pending membership creation. An ambiguous provider timeout is preserved for reconciliation; another provider entity is not blindly created. The bounded history scan finds `academy_attempt_id` notes. If the entity falls beyond the scan or was never created, staff must inspect provider history before resolving the attempt. Refund requests use Razorpay's documented `X-Refund-Idempotency` header with the durable refund job UUID.

Official references: [court checkout verification](https://razorpay.com/docs/payments/payment-gateway/web-integration/standard/integration-steps/), [webhook verification/retries](https://razorpay.com/docs/webhooks/validate-test/), [subscription creation](https://razorpay.com/docs/api/payments/subscriptions/create-subscription/), [paid subscription invoices](https://razorpay.com/docs/api/payments/subscriptions/fetch-invoices), [cycle-end cancellation](https://razorpay.com/docs/api/payments/subscriptions/cancel-subscription/), [idempotent refunds](https://github.com/razorpay/markdown-docs/blob/master/api/refunds/normal-refunds-idempotent.md).

## Scheduling, refunds and staff records

Configure a scheduler to call `GET /api/cron/reconcile` every five minutes with `Authorization: Bearer <CRON_SECRET>`. It expires holds and processes bounded payment, refund, cancellation and failed-webhook batches. Deploy this endpoint on a runtime supporting its 120-second maximum duration. Returned nonzero `failed`/`unresolved` counts require monitoring; create an alert outside the public site. Attempts are processed fairly by their last reconciliation time; failed events have backoff and unfinished event leases can recover. Provider webhook delivery remains the primary payment signal, scheduler reconciliation is recovery. The read/hold paths also repair expired holds; public availability generates the rolling fourteen-day grid from real allocations, so it has no stale seeded slots. The existing project is deployed on Vercel. Vercel Hobby is limited to one cron execution per day, which does not meet this endpoint's five-minute schedule, and Hobby is restricted to personal/non-commercial use. Verify the actual account plan and function limits. Do not upgrade or incur charges without renewed authorization; select a compatible scheduler/runtime or make and test a bounded-work change before scheduling.

Staff cancellation requires a reason, accepts zero/full/partial refund, releases occupancy atomically and preserves a pending gateway refund until provider confirmation. A refund API failure does not silently claim the money returned. Check pending `academy_refunds`, failed `academy_webhook_events`, reconciliation attempts and `academy_audit` daily. A processed refund is recorded once. Additional captured payments on an already settled booking are refunded separately and cannot change the reservation or falsely refund its original valid payment.

Manual walk-ins/phone/platform records default to unpaid. Staff explicitly records cash/external/not-required with a reference or reason; Playo/Hudle/District requires its platform reference. No automatic external synchronization is claimed. Schedule “Recorded receipts” totals include recorded external payments, cash and verified gateway captures; refunds include recorded external/cash returns and processed gateway refunds, including duplicate/late captures. They do not imply bank settlement.

Member individual-play reservations are staff-only. A zero-priced linked member session must fall today, be covered by paid membership, and atomically consume that member's daily attendance. A previously recorded standalone visit consumes the included benefit, so a further free reservation is refused. Paid court bookings remain INR400 for a paid member whose membership covers the chosen start, INR500 otherwise. Staff amount overrides require a reason. Retaining a recurring subscription after missed renewal prevents creating a competing mandate: it becomes past_due with no benefits until a paid invoice arrives, or the member cancels and rejoins. Cancellation requests survive provider/database interruptions and are reconciled; paid-through access remains until the verified paid period ends.
